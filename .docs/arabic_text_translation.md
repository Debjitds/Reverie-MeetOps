# 26. Important Localization Rules

1. Use **Modern Standard Arabic (العربية الفصحى)** throughout the application.
2. Use natural Arabic UI terminology rather than literal word-for-word translations.
3. Preserve all dynamic values exactly.
4. Preserve all variables/placeholders exactly, including:

   * `{resource}`
   * `{user}`
   * `{days}`
   * `{count}`
   * `{date}`
   * `{time}`
5. Do not translate:

   * usernames
   * email addresses
   * room names stored as database values
   * dynamically generated booking purposes
   * dates and times
   * numeric values
6. Do not translate technical identifiers, API values, database enum values, or code variables unless they are explicitly displayed as user-facing text.
7. Arabic interface direction must be **RTL**.
8. Numbers, dates, times, and dynamic database content must remain readable and must not be corrupted by RTL rendering.
9. Keep the existing Neo-Brutalist visual design unchanged.
10. Do not modify business logic while implementing localization.
11. English must remain fully functional when English is selected.
12. Arabic must apply consistently across every page, modal, dropdown, toast, notification, empty state, validation message, and AI-related static UI text.

# 28. RTL Requirement

When Arabic is active:

```text
dir="rtl"
```

should be applied to the application/root localization container.

The UI must correctly support:

* RTL text direction
* Arabic headings
* Arabic navigation
* Arabic tables
* Arabic dropdowns
* Arabic modals
* Arabic notifications
* Arabic toast messages
* Arabic form labels
* Arabic placeholders
* Arabic pagination
* Arabic calendar labels

Do not mirror icons that are universally directional-neutral.
Only mirror directional icons where necessary for RTL usability.
